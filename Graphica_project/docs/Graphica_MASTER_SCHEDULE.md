# Graphica マスタースケジュール

これまで作成した複数のドキュメント(機能バックログ・プラグインAPIロードマップ・GUIロードマップ)を、**1つの実行順序**として統合したもの。Claude Codeに作業を依頼する際は、まずこのファイルで「今どのトラックのどの項目に着手すべきか」を確認してから、該当する詳細ドキュメントを参照する使い方を想定している。

## 関連ドキュメント一覧

| ファイル | 役割 |
|---|---|
| `Graphica_SPEC.md` | 本体の仕様・アーキテクチャ(常に必須の前提知識) |
| **`Graphica_MASTER_SCHEDULE.md`**(本ファイル) | 全体の実行順序 |
| `Graphica_ROADMAP_PLUGIN_AND_GUI.md` | プラグインAPI拡張(フェーズA〜G)+GUIモダン化(フェーズH)の詳細手順 |
| `Graphica_CORE_BACKLOG.md` | 本体機能135件の詳細(本ファイルでタイミングを付与) |
| `Graphica_PLUGIN_BACKLOG.md` | プラグイン本体64件の詳細(トラック4と並行して着手) |
| `Graphica_INTEGRATION_REPORT.md` | 上記バックログを作った際の分析・振り分け根拠(背景資料、実行時は必須ではない) |

## 全体の流れ(5トラック)

```
トラック0: 着手前提条件(必須・最優先)
    ↓
トラック0': クイックウィン(トラック0と並行、いつでも着手可)
    ↓
トラック1: プラグインAPI拡張(フェーズA〜G)
    ↓
トラック2: GUIモダン化(フェーズH)
    ↓
トラック3: 残りの本体機能追加
    ↓ (トラック3と並行)
トラック4: プラグイン本体の開発
```

**判断ルール**: 新しい作業に着手する前に、必ずこのファイルで「その項目がどのトラックか」「前提条件を満たしているか」を確認する。トラック番号が若いものを優先する。同じトラック内は上から順で良いが、厳密な順序指定がない限り並行着手も可。

## Claude Codeへの依頼テンプレート

新しいセッションを開始する際、最初のメッセージの型として以下を推奨する。

```
docs/Graphica_MASTER_SCHEDULE.md を確認し、現在のトラック・フェーズを特定して。
着手前提条件(トラック0)が完了しているか docs/PLUGIN_API_PROGRESS.md で確認し、
未完了ならその旨を報告して(勝手に前提条件を実装しない)。
完了していれば [対象フェーズ/項目] のみ着手して。
完了条件を全て満たしたら pytest を実行し、進捗ファイルを更新してコミットして。
```

「[対象フェーズ/項目] のみ着手して」で範囲を絞るのが引き続き重要。マスタースケジュール全体を渡しても、Claude Codeが自律的に全トラックを一度に進めようとしないよう、都度スコープを指定すること。
