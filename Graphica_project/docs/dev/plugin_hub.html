Graphica プラグイン開発ハブ

プラグインは1つずつ別のチャット・別のリポジトリで開発します。このページは、どのチャットからも同じ前提で始められるようにするための共通の資料と、全件の進捗ボードです。状態はこのページのデータベースに保存され、各チャットが更新します。

着手順

進め方の全体像

ユーザーはこのボードで対象のプラグインを開き、「引継ぎプロンプト」をコピーして新しいチャットに貼り付けます。貼り付けられたチャットは、このページ(https://claude.ai/artifact/GZ3LTLJjbxj1LQsAhZFg2o)を Artifact ツールの action: "read" で読んでから、次の手順で進めてください。

手順

  1. ハブを読み、状態を「進行中」にする

    このページの「共通ルール」「API 早見表」と、担当プラグインの項目を読みます。着手したら、データベースの plugins/<ID> を state: "in_progress" に更新します(書き方は「共通ルール」の最後)。

  2. 仕様をユーザーと決める

    各項目の「着手前に決めること」をユーザーに確認してから実装に入ります。対象範囲(対応するファイル形式の種類、検定の種類など)は工数を大きく左右するので、選択肢と推奨を示して1回で決めてもらいます。

  3. リポジトリを作る

    名前は graphica-plugin-<name>(各項目に候補があります)。GitHub への作成・push は外部に公開する操作なので、ユーザーの了承を得てから行います。ローカルの置き場所は、本体の PlotterApp と同じ階層に graphica-plugins/ フォルダを作り、その中にまとめるのが推奨です。

    gh repo create STsuruga/graphica-plugin-<name> --public --description "Graphica用プラグイン: …(P-xxx)"
git clone https://github.com/STsuruga/graphica-plugin-<name>.git

    雛形は graphica-plugin-element-constants(P-805)です。次のファイルをコピーして、プラグイン名の部分だけ書き換えます。

    ファイルそのまま使える?役割
    tests/conftest.pyそのままoffscreen の QApplication と、本体が無い環境でテストを skip する requires_graphica
    scripts/build_zip.pydocstring の例だけインストール可能な zip(トップレベルにプラグインフォルダが1つ)を dist/ に作る
    .gitignore / requirements-dev.txtそのままdist/ などの除外、テスト依存
    README.md構成を流用できること / インストール / 開発環境 / zip のビルド / 構成
    雛形リポジトリには LICENSE と CI がまだありません。新しいリポジトリでは LICENSE(MIT、本体と同じ)を最初から置いてください。CI は「共通ルール」の雛形を使えますが、まだどのリポジトリでも動作確認していません。最初に使ったチャットが動作を確かめ、このページに結果を反映してください。

  4. 開発環境をつなぐ

    pip install -e ../../PlotterApp/Graphica_project   # 本体を editable install(パスは置き場所に合わせる)
pip install -r requirements-dev.txt
pytest

    これで from graphica.plugin import Dataset と from graphica.plugin.testing import … が使えます。本体の内部(core など)は import しません。

  5. 実装とテスト

    計算処理は GUI にも本体にも依存しないモジュール(例: analysis.py)に分け、純粋な関数として単体テストします。register(api) の配線と窓口を使う処理は FakeGraphicaPluginAPI / FakePluginContext で、実際の読み込み経路は load_plugin_like_graphica(本体と同じ読み込み処理)で確認します(相対 import の誤りや api_version の不一致はこのテストでしか見つかりません)。どれも graphica.plugin.testing にあります。

  6. 本体に入れて動かす

    python scripts/build_zip.py --all で zip を作り、Graphica をソースから起動(python main.py)して 編集 ▸ 環境設定 ▸ プラグイン ▸ プラグインをインストール... から入れ、再起動して実際に操作します。画面を伴う機能は、ユーザーにも実機で確認してもらいます。

  7. リリースする

    plugin.json の version とタグを揃え、zip を GitHub Release に添付します(zip はリポジトリにコミットしません)。

    git tag v1.0.0 && git push origin v1.0.0
gh release create v1.0.0 dist/<plugin_name>-1.0.0.zip --title "v1.0.0" --notes "…"

  8. ハブを更新する

    state: "done"、repo、version、release_url、note を書き込み、更新後の状態をユーザーに表で示します。本体リポジトリの docs/dev/PLUGIN_DEVELOPMENT_PROGRESS.md の表にも1行追記します(本体への書き込みはこの記録だけ)。

各リポジトリに置く CLAUDE.md の雛形

次のセッションが前提を失わないよう、リポジトリ直下に置きます。<…> を埋めてください。


      

    

  


  
  

    

      

        
守ること

        
Graphica 本体のコードは変更しない。フックが足りない、本体の不具合を見つけた、といった場合は実装を止めて、Graphica の Issue に「必要な拡張点と、プラグイン側で何ができなかったか」を書き(作成はユーザーの了承を得てから)、ハブの note にも残します。回避策で本体の非公開メソッドに深く依存するのは避けます。

        
使えるのは本体が同梱しているパッケージだけ。標準ライブラリ、PySide6 / matplotlib / numpy / pandas / scipy / openpyxl / xlrd。配布版(exe/app)にはこれ以外が入っていません。h5py や plotly などが必要な項目は、着手前に「pip 版だけで動くプラグインにするか」をユーザーと決めます。使うモジュールは plugin.json の requires に書くと、無い環境で明確なメッセージとともにスキップされます。

        
プラグインフォルダ内の import は相対 import。本体はプラグインを graphica_plugin_<フォルダ名> という動的モジュール名で読み込みます。from .analysis import … と書き、from my_plugin.analysis import … とは書きません。プラグイン同士も import できません(他プラグインのコードを使うならコピーして同梱)。

        
元のデータを書き換えない。processor / analyzer は受け取った Dataset やその df を変更せず、新しい Dataset を返します。追加は本体が Undo 付きで行います。

        
結果は構造化して返す。analyzer の結果は文字列に詰め込まず、AnalysisResult の table(DataFrame)/ annotations / new_datasets に分けます。表示・CSV 出力・Undo は本体側が面倒を見ます。

        
本体から import してよいのは graphica.plugin と graphica.plugin.testing だけ。Dataset / AnalysisResult は from graphica.plugin import …、偽物と読み込みの確認は graphica.plugin.testing。core / gui / models は本体の内部で、I-1 で graphica.* の下へ移るので、直接 import すると壊れます。

        
本体とは窓口 ctx(PluginContext)だけでやりとりする。メニューの callback とパネルの widget_factory には、そのタブの窓口 ctx が渡ります。データセットの取得・追加・変更(Undo 付き)、再描画、変化の通知、メッセージ表示、プラグイン専用の保存フォルダ(ctx.data_dir)、登録色と配色パレットの読み書きは、すべて ctx で行います。本体の内部(PlotterApp、_ で始まるメソッド、QSettings のキー)には触りません。メニューで受け取った ctx を保存して別のときに使うと別のタブを操作してしまうので、使い回さないでください(パネルは自分の ctx を持ち続けてよい)。

        
すべて GUI スレッドで同期実行される。重い計算(数秒以上)はそのまま UI を止めます。点数に上限を設ける、間引く、処理前に件数を示すなどで対処し、ハブの note に計測値を残します。

        
表示名は英語か日本語をそのまま渡す。本体の翻訳機構(tr())にはつながりません。メニュー名・パネル名は、利用者が主に使う言語で1つに決めます(既存の P-805 は日本語)。

register(api) で使えるフック

        
どのフックも例外を投げず、失敗すると False を返してログに記録します(画面には何も出ません)。メニューの callback と processor / analyzer などの実行時の失敗は、プラグイン名付きのエラーとして画面に出ます。動かないときは %LOCALAPPDATA%\Graphica\graphica.log を見ます。同じ名前の二重登録は失敗します。

        

          
フック渡すもの画面のどこに出るか

          
            
register_fit_function(name, func, param_names, p0=None)func(x, *params)。p0 はリストか (x, y) -> list曲線フィットのモデル一覧

            
register_menu_action(text, callback, shortcut=None)callback(ctx)(選んだときのタブの窓口)「プラグイン」メニュー

            
register_importer(extensions, loader, *, name=None, priority=0)loader(path) -> pandas.DataFrame(1つだけ。複数ブロックは未対応)ファイルを開く・ドラッグ&ドロップ・フォルダ一括

            
register_exporter(format_name, extension, writer, *, name=None)writer(Figure, path)エクスポートとバッチエクスポートの形式

            
register_processor(name, fn, *, category="general", param_schema=None)fn(Dataset, params) -> Dataset(新しいもの)プラグイン ▸ データ処理 ▸ category

            
register_analyzer(name, fn, *, output_kind="table", param_schema=None)fn(Dataset, params) -> AnalysisResultプラグイン ▸ 解析(選択中のデータセットに対して実行)

            
register_panel(name, widget_factory, *, area="right")widget_factory(ctx) -> QWidget。タブごとに呼ばれる。初期状態は非表示。ctx.on_datasets_changed / on_selection_changed で表示を更新ドックパネル(プラグインメニューから表示)

            
register_plot_type(type_name, drawer, *, requires_2d=False)drawer(Dataset, Axes, x, y) -> Artist|None。x, y はウォーターフォール等を適用済みプロパティの「種別」

            
register_render_backend(name, backend)登録されるだけで、描画にはまだ接続されていない(なし)

          
        

      


      

        
Dataset を作るとき

        
name / df / x_col_name / y_col_name は必須です(本体の古いガイドの例には抜けているものがあります)。


from graphica.plugin import Dataset

new_df = pd.DataFrame({"energy_eV": e, "tauc": t})
return Dataset(name=f"{dataset.name} (Tauc)", df=new_df,
               x_col_name="energy_eV", y_col_name="tauc", color=dataset.color)

        
読むときは dataset.x_data / dataset.y_data(マスクした行を除いた配列)を使います。行番号で df に戻る場合は dataset.visible_df を基準にします。誤差列は x_err_data / y_err_data、2Dマップは data_kind == "2d_grid" と z_col_name。

      


      

        
AnalysisResult の annotations

        
現在のサブプロットに注釈として追加されます(Undo 対応)。座標はデータ座標です(stat だけ軸の相対座標 0〜1)。

        

          
typeキー用途

          
            
"text"xy: [x, y], text, colorピーク値などのラベル

            
"arrow"xy(矢の先), xytext(文字の位置), text, arrow_style: "single" | "double" | "bracket", arrow_curvature, colorbracket は有意差ブラケット(P-402)の土台

            
"vspan" / "hspan"range: [lo, hi], color, alpha積分範囲・帰属バンドの強調

            
"stat"dataset_id, stat: "mean" | "std" | "max" | "min" | "r_squared", xy(軸の相対座標)データに追従する統計値ラベル

複数のデータセットを入力にしたいとき

  • 1つのデータセットの列で表す: 群を表す列(カテゴリ)や、条件ごとの列を持つ表を入力にする。analyzer のままで作れて、テストも簡単。

  • パネルで選ばせる: register_panel の widget_factory に渡る ctx の datasets() / selected_datasets() から一覧を作り、結果は ctx.add_dataset()(Undo 付き)で追加する。ctx.on_datasets_changed で一覧を最新に保つ。
