## 絶対条件(ユーザーの指示、2026-09-25、原文)

> 【絶対条件(維持すること)】・既存のすべての機能、入力と出力の仕様、および副作用は完全に維持してください。・既存のエッジケースの挙動も変わらないようにしてください。
> 【変更してよいこと(改善の方向性)】・アーキテクチャ、クラス/モジュール設計、関数の切り出し方などの内部構造は、根本から変更して構いません。・可読性、保守性、再利用性が最大化される、モダンで最適な設計を提案してください。
> もし改善案の思考途中や改善中に絶対条件の内容におけるバグや改善事項があれば順次新規改善案として提案して欲しい。

ここから決めた運用:

- **今の不具合も「今の挙動」として維持する。** 見つけても直さず、K として db に登録し、ユーザーに提案する。
- 直すのは、ユーザーが選択肢から選んだあと、別ブランチ `fix/k<n>-…` の別 PR で。再現するテストを先に書く。
- 「挙動を変えていない」ことは R-0 の特性テストで示す。**`refactor:` コミットでは `tests/characterization/golden/` が 1 バイトも変わらない。**
  基準を更新してよいのは `fix:` コミットだけで、コミットの本文に理由を書く。
- **既存のテストのアサーションは変えない。** R のコミットで既存テストに入れてよい変更は、import の場所と
  monkeypatch の差し替え先(コードを移したので)だけ。入れたら PR の本文に一覧を書く。

## ブランチと取り込み

1. 段階の作業ブランチを `refactor/architecture` から切る。
2. 段階が終わったら、特性テストとフルスイートを通す。
3. ユーザーの承認を得てから、`refactor/architecture` 向けの PR を作る。マージもユーザーの承認後。
4. その段階のあとに直す K(ロードマップの「このあとに直す改善案」)について、選択肢をユーザーに示す。
   選ばれたものを `fix/k<n>-…` で直し、別 PR にする。
5. マイルストーン(M1〜M5)の始めに master を統合ブランチへマージする(master には緊急の修正しか入らない想定)。
6. M6 の V-1〜V-5 がすべて済んだら、ユーザーの承認を得て `refactor/architecture` → master の PR を作り、マージする。
   **master への統合はこの 1 回だけ。** 途中の段階を master に入れない。

CI の `pull_request` は今 master 向けにしか動かない。P-2 で `.github/workflows/build.yml` の
`pull_request.branches` に `refactor/architecture` を足す(push の条件とカバレッジの条件は変えない)。

## 1 ステップの型

1. 作業ブランチで実装する。コミットは層ごとに分ける(例: 部品の追加 → 呼び出しの置き換え → 古いコードの削除)。
2. 関係するテストと特性テストを回す。`core/`・共有の部品・`conftest.py` を触ったらフルスイート。
3. コミットしてプッシュする。末尾に `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`。
4. ロードマップの db `steps/<ID>` を `state: "done"` にし、`note` に要点(コミット ID、数字)を 1〜2 文で書く。
   `ArtifactData` の `update`、`if_version` を付ける。ページを作り直す必要はない。
5. `CURRENT_STATE.md` の「現在地」を上書きする。
6. ユーザーに進捗表(マイルストーン・ステップ・K の状態)を見せる。

コミットの種類: `test:`(R-0 の特性テスト)、`refactor:`(構造だけ、基準は不変)、`fix:`(K の修正、基準の更新あり)、
`ci:`、`docs:`。コメントは `CONTRIBUTING.md` の方針(日本語、なぜと制約だけ、項目番号や経緯は書かない)。
移したコードのコメントも同じ方針で最小にする。

## テストの回し方

- 1 つのファイル: `pytest tests/test_x.py`(`-k` で絞るときは先に `--collect-only -q` で件数を数える)
- 特性テスト: `pytest tests/characterization`(R-0 のあと。すべての段階で毎回回す)
- フルスイート: `bash scripts/run_tests_chunked.sh`(約 18 分)。**1 プロセスの `pytest` で全件を流さない。**
  長く回すときは scratchpad に一時的な worktree を作り、そこで回すと作業を続けられる。
- 進み具合は 30 分ごとに「完了チャンク数/全体(%)」で報告する。止まっていないかは CPU 時間の差で見る。
- `tests/test_export_preview_panel.py` は終了時に落ちる(exit 139)が、`N passed` があれば既知の問題で緑扱い(`!!! WARN`)。
- カバレッジは V-1 で `bash scripts/run_coverage.sh`(下限 92%)。途中では測らなくてよい。

## 知っておくこと

- `tests/conftest.py` は `GRAPHICA_CONFIRM_UNSAVED_CHANGES=0` と `QT_QPA_PLATFORM=offscreen` を設定し、
  テストごとに残ったウィンドウを破棄する(`destroy_leftover_windows`)。これを壊すとスイートが倍遅くなる。
- テストは PlotterApp と mixin の非公開メソッド 286 個のうち 159 個を直接呼ぶ。R-7・R-8 で中身を移しても、
  これらの名前は PlotterApp に委譲として残す(K-26)。
- テストが monkeypatch するモジュールの属性(例 `main_window_module.QFileDialog` 29 か所)は、コードを移すと効かなくなる。
  移したコミットで差し替え先も移す。漏れは R-0.1 の仕掛け線で失敗として出る。
- 描画・メニュー・プロパティ欄・プラグインの注意は `CLAUDE.md` の各節にある(組み立ての順番、`allow_reuse`、
  `menuAction()` の保持、`sender()`、`triggered` 接続など)。
- 会話は日本語。選択肢は AskUserQuestion で示す。PR の作成とマージは必ずユーザーの承認を得てから。
