2026-10-12基準: master ed0cad1見本: docs/dev/mockups/gui_redesign/final_lite_advanced.html

1設計の原則

  1. 部品は1組だけ作る。Lite と Advanced で別の画面を作らず、同じ部品の表示・非表示だけを切り替える。どの部品がどちらのモードに出るかは1つの表(gui/ui_mode.py)に書く。
  2. 今の部品を「値の持ち主」として残す。線の種類のセグメントボタンやトグルのような新しい見た目の部品は、今の QComboBox・QCheckBox・QDoubleSpinBox と同じ使い方ができる形で作るか、今の部品と同期させる。DATASET_PROPERTY_BINDINGS・AXIS_BINDINGS・特性テストの property_bindings を壊さないため。
  3. 色はトークンだけで決める。QSS・QPalette・matplotlib の背景・ミニマップ・起動画面まで、gui/theme.py のトークンから取る。アクセントは利用者が選んだ1色から計算する。
  4. 保存形式は変えない。プロジェクト(.gra)には何も足さない。新しい設定(モード・テーマカラー)は gui/app_settings.py の表に1行ずつ足す。
  5. モードを切り替えても値は変わらない。隠すだけで、リセットも書き戻しもしない。content_fingerprint() が切り替えの前後で同じことをテストで確かめる。
  6. プラグイン API は変えない。register_panel のパネルは帯の「プラグイン」に入る。area は置き場所の希望として読む。

テーマカラーから色を計算する

Qt に依存しない純粋な関数として gui/theme_color.py に置き、Qt なしでテストします。モックアップの JavaScript と同じ手順です。

derive(選んだ色, dark) -> {accent, accent_fg, on_accent, accent_soft}
  背景 = dark ? surface(#181B1F) : #FFFFFF
  accent    = 明るさ(HSL の L)だけを 0.01 ずつ動かし、背景とのコントラスト比が 4.5 以上になるまで
              (ライトは暗く、ダークは明るく。色相と鮮やかさは変えない)
  accent_fg = accent からさらに同じ向きに、比 4.5(ライト)/ 7(ダーク)以上まで
  on_accent = 白と #0C0E11 のうち、accent との比が大きい方
  accent_soft = accent を透明度 12%(ライト)/ 18%(ダーク)で
コントラスト比は WCAG 2 の相対輝度で計算する
選んだ色ライトの accentダークの accentダークの accent_fg補正
アイコン(既定)#0F4C5C#1D91AF#24B5DBダークで明るく
ブルー #2563EB#2563EB#4A7EEE#82A6F3ダークで明るく
イエロー #FACC15#8C7103#FACC15#FACC15ライトで濃く。ダークのボタンの文字は黒
薄いグレー #E5E7EB#6A758A#E5E7EB#E5E7EBライトで濃く

この表をそのままテストの期待値にします。ほかに、ランダムな色を数百個与えて、どれも比 4.5 以上になることも確かめます。設定には「選んだ色」だけを保存し、補正は毎回計算します。

Qt への当て方

  • QPalette をトークンから作る。今はライトのとき OS のパレットのままで、ダークは固定の (53,53,53) です。両方ともトークンから作ります。palette(base) などを使うプラグイン(color-studio、mass-spec)と、Qt 標準のダイアログが揃います。
  • apply_theme() の省略の条件に色を入れる。今は「ダークかどうか」が同じなら処理を省いていますが、テーマカラーを変えたときも作り直す必要があります。条件を (dark, 選んだ色) にします。
  • 色を焼き込んだアイコンを作り直す。スピンボックスの矢印の PNG は、ファイル名に色が入っているのでそのまま使えます。icon_utils.icon() のアイコンは、テーマカラーを変えたときにも _refresh_custom_svg_icons を呼びます。
  • キャンバス・ミニマップ・起動画面。rendering/common.py の DARK_FIGURE_FACECOLOR はすでに DARK_TOKENS['surface'] です。値が変わるので、ダークの描画のゴールデンが変わります(6)。minimap_widget.py の固定の色はトークンに替えます。
  • 文字の大きさ。モックアップの本文は 13px で、今のアプリのフォントは 9.5pt(96 dpi で約 12.7px)です。差は小さく、変えると文字の幅に関わるテストやゴールデンが広く動くので、9.5pt のままにします。

4Lite と Advanced の仕組み

  • 設定: UI_MODE = Setting("ui_mode", …, str, export_as=str) と THEME_ACCENT_COLOR = Setting("theme_accent_color", "#0F4C5C", str, export_as=str) を gui/app_settings.py に足します。既定のモードは、初めて起動した人は Lite、今の利用者は Advanced です(9 の 1)。設定に ui_mode が無いとき、has_shown_welcome が真なら今の利用者とみなして Advanced を書き込みます。画面の表示名は日本語が「シンプル / 詳細」、英語が Lite / Advanced です。
  • 表: gui/ui_mode.py に、部品の名前(タブの属性名)と出すモードの組を並べます。例: ('stats_row_advanced', ADVANCED)、('type_tiles', LITE)、('bottom_panel', ADVANCED)。apply_ui_mode(app, mode) がこの表を見て setVisible() します。
  • プロパティの行: DATASET_PROPERTY_BINDINGS の各行に「Lite でも出すか」の列を足します。表示の判定は「今の条件 かつ モードの条件」です。
  • 全タブで同時に: モードとテーマカラーはアプリ全体の設定です。MainAppWindow が全タブに知らせます。後から開いたタブは、作るときに今のモードで組み立てます。
  • 切り替えは軽く: 切り替えでは QSS を当て直さず、表示・非表示だけにします(setStyleSheet() は1回約 130ms)。
  • Lite で隠れている設定が使われているとき: 案内の枠に「使用中: グラデーション」のように出すと、見えない設定に気付けます(提案。モックアップには無い)。
  • メニューとショートカット: 両方のモードで同じです。Lite でも ≡ からすべての機能に届きます。

5PR の段取り

ブランチの運用

大きな変更なので、master には最終確認ができてから入れます。refactor/architecture のときと同じ形です。

  1. 統合ブランチを作る。master から feature/gui-redesign を切る。最初のコミットで .github/workflows/build.yml の pull_request.branches に feature/gui-redesign を足す(今は master と refactor/architecture だけなので、足さないと統合ブランチ向けの PR で CI が走らない)。
  2. 各 PR は統合ブランチへ向ける。下の PR 0〜9 は、すべて feature/gui-redesign から切り、feature/gui-redesign にマージする。CI が全部通れば確認なしでマージしてよい(今の運用と同じ)。macOS 実機の確認が要る PR(3 と 9)は、確認を取ってからマージする。
  3. master の変更を取り込む。刷新の途中で master に入った修正は、区切りごとに統合ブランチへマージする。インストーラーと exe の確認(package.yml)は master 向けの PR でしか自動で走らないので、区切りで手動実行(workflow_dispatch)する。
  4. 最終確認。PR 9 の後、統合ブランチから exe を作ってユーザーが実際のアプリで確かめる。直すものがあれば統合ブランチで直す。
  5. master へ。ユーザーの了承を得てから、feature/gui-redesign → master の PR を作ってマージする。build.yml に足した統合ブランチの行は、その後に外す。

番号は作業の順番です。各 PR の中は、CLAUDE.md の規律どおり「部品 → 組み込み → 配線 → テスト」の層ごとにコミットを分けます。どの PR も gui/theme.py か画面の骨組みに触れるので、マージ前に scripts/run_tests_chunked.sh でフルスイートを回します。

8リスク

リスク対策
メニューバーを隠すと、ショートカットが効かなくなる表から作った全部の QAction をタブにも足す。テストで主なショートカットを押して確かめる
macOS はメニューバーが画面の上にあり、≡ と二重になるmacOS ではネイティブのメニューバーを残し、≡ は同じメニューを出すだけにする。実機の確認はユーザーに依頼する
保存したドックの配置が新しい配置と合わないDOCK_LAYOUT_VERSION を上げて既定の配置に戻す。名前を付けて保存した配置(プリセット)が戻せないときは警告を出す
タブごとの QMainWindow の作りと、アプリ全体の上部バーの組み合わせ上部バーは MainAppWindow に1つだけ置き、表示中のタブの操作を付け替える。タブは今までどおり独立させる
見え方を変えると、値の対応(バインディング)が壊れる今の部品を値の持ち主として残す(原則 2)。property_bindings・axis_bindings の特性テストは変わらないはず
英語の文字が長く、幅 340 に収まらないtests/test_english_ui.py と幅の確認。訳を短くする
ゴールデンの作り直しが毎回入る作り直しのコミットを分け、何が変わったか(配置・色)を本文に書く
プラグインの独自スタイル(mass-spec の文字 11px)パレットはトークンから作るので大半は揃う。残りはプラグインのリポジトリで直すよう、ハブで知らせる
